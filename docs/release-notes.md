## 修掉「不该响的时候响」

- **活跃时段之外不再提醒。** 打卡重排原先只比了窗口的上界，于是「09:00 开始」的时段里，
  早上 07:00 记一杯会排出一个 07:45 的提醒。现在朴素间隔必须真落在窗口内才作数。
- **人离开后的重试不再越界。** 重试点原先直接写「现在 + 5 分钟」：窗口终点那个提醒点
  顺延 5 分钟就跑出时段；窗口终点靠近午夜时还会跨到次日，在「仅工作日」的周六弹通知。
- **节假日数据坏掉不再崩。** 本地缓存原先只校验年份和更新时间，缺字段的脏数据会一路
  进到判定里抛异常，而它跑在 10 秒一次的巡检上。现在读盘走与网络来路同一套严格校验，
  脏数据只降级成「按星期判定」，界面照旧提示去更新。

## 新增：活跃时段支持跨夜

- 结束时间不晚于开始时间即为跨夜时段（`21:00 – 09:00`）；两者相同就是整天时段。
- 跨夜窗口归属它的**开始日**：`21:00–09:00` 配上仅工作日，含义是
  「周五晚上到周六早上照常提醒、周六晚上到周日早上不提醒」；凌晨那半截算前一天的窗口，
  提醒栅格也从那一刻起算（所以 `00:00` 可以是一个正常提醒点）。
- 设置面板会写明「跨夜时段：从 21:00 一直提醒到次日 09:00」，不用猜。
- 起点 >= 终点不再退化成「按间隔全天乱弹」——那是旧版本在时段设反时的行为。

## 数据文件：读盘一律合法化

数据文件会被手改、被旧版本写过、被别的工具改写，所以设置项和记录在读取时都要过一遍规则：

- **记录来源非法会让界面白屏。** 来源不是已知值时，界面会把整个对象交给 React 当子节点，
  实测 React 报 #31、`#root` 长度归零、窗口一片空白，而主进程没有任何异常。
  现在来源不在白名单就回落成「手动」。
- **记录本身**：毫升数 0/负数/非有限值整条丢弃，超范围但合理的夹到 10–2000，
  时间戳非有限丢弃，重复或缺失的 id 重新分配，并按时间排序（否则「撤销上一次」会撤错）。
  读盘还会丢掉未来时间戳，否则撤销会去删那条今天看不见的记录。
- **设置项**：间隔、时段、目标等非法值一律丢掉、由默认值兜底。旧版本未校验时实测过
  `intervalMin` 写成 `null` 会被夹成 5 分钟（比设置的还勤）、写成字符串会让当天剩余的
  提醒全丢。
- 节假日缓存写入改为原子替换（临时文件 + fsync + rename），和数据文件一致。

## 其它

- 窗口端点改用本地时间构造，夏令时切换日不再整体偏移一小时。
